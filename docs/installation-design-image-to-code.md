# Install design-image-to-code for pi

[design-image-to-code](../skills/design-image-to-code/SKILL.md) is a Pi skill bundled in this repository. Hand the agent a design image — a screenshot from the designer, a mockup, a Figma export, or a local reference image, optionally with a Figma / MasterGo / Lanhu annotation link or cut assets — and it follows one loop:

```
design image input (annotations optional)
→ image analysis
→ implementable spec
→ map onto the existing project
→ implement
→ render and compare
→ visual iteration
```

The supplied design image defines the target, not a new design generated by the agent. Evidence has distinct responsibilities, defined in the skill's **证据裁决** section:

- Images establish composition, hierarchy, content, and non-numeric shape.
- Explicit annotations govern assignable properties such as dimensions, font size, and color; applicable tokens come next, then approximate image measurements. A visual estimate does not silently override an annotated value.
- Asset references and export mappings connect images, icons, and fonts to design regions, checked against the image and project resources.
- Cross-source conflicts stay in the discrepancy log. Unresolved conflicts affecting structure, brand, key line wrapping, or interaction require confirmation.

Browser bounding boxes and computed styles verify the implementation; they are not independent design evidence. With annotations but no image, the agent requests the image. Unspecified content receives only the minimum implementation needed for functionality, without inventing a visual direction. The skill text is written in Chinese.

## Install

The skill lives at [`skills/design-image-to-code/`](../skills/design-image-to-code) in this repository. From a clone of the repo:

```bash
mkdir -p ~/.pi/agent/skills
cp -R skills/design-image-to-code ~/.pi/agent/skills/
```

The repository copy is the distribution source; the installed copy is a snapshot, not a live link. Make shared changes in `skills/design-image-to-code/SKILL.md`, then copy it again. If the installed file has local edits, reconcile them before copying rather than overwriting them blindly.

The layout after copying:

```
~/.pi/agent/skills/
└── design-image-to-code/
    └── SKILL.md
```

> Install at the **global** level to use it in every project, or copy it into a project's `.pi/skills/` directory to scope it to that repository.

## Verify

In a fresh `pi` session:

- Run `/skill:design-image-to-code` — the command loads the skill explicitly.
- The skill also auto-loads when a request matches its description (design image → frontend code).
- Attach a small design image and target an existing page; confirm image analysis and project mapping precede editing.
- For a 16px annotation that looks closer to 18px in the image, expect the annotated value plus a recorded conflict, not an unreported visual override.
- With an unknown viewport, expect a documented assumption and a pending acceptance-size status even after a screenshot comparison.
- Without a working renderer, expect an explicit visual-verification blocker, not a claim that a successful build proves fidelity.

These are manual behavior checks to run after installation, not claims that the skill has already passed an end-to-end evaluation.

## Activate

Restart pi, or run `/reload` inside an existing pi session after copying the files.

## Configure

Optional. Add a routing hint to your global `~/.pi/agent/AGENTS.md` so the agent reaches for the skill deliberately:

```markdown
## Frontend workflow

- For requests that provide a design image (screenshot, mockup, Figma export, or local reference image, optionally with design annotations) and ask to translate that specific interface into frontend code, use `design-image-to-code`.
```

The skill can implement code without a working browser, but cannot pass visual verification without rendered comparisons. When [agent-browser](installation-agent-browser.md) is available, the skill reads and follows it for browser operations. Otherwise it uses existing preview/E2E/screenshot capabilities and reports any coverage gaps; it does not install tools merely to force a pass.

## Uninstall

```bash
rm -rf ~/.pi/agent/skills/design-image-to-code
```

## Scope

- One responsibility: supplied design image → existing frontend code; no new art direction, general planning, independent code review, or design-system project.
- Preserve the stack, business logic, permissions, and control semantics. Prefer scoped component overrides; confirm global theme changes or component replacements.
- Missing assets are triaged by impact: confirm brand/primary-layout dependencies, record low-impact substitutes, and continue unaffected regions.
- Region IDs connect specifications, file mappings, and discrepancy/retest records across the agreed images, states, and viewports.
- Comparisons fix viewport/DPR, fonts, locale, permissions, data, and animation state. Two rounds without improvement stop refinement, not the acceptance checks.
- The workflow remains in one `SKILL.md`; `agent-browser` is an optional execution integration, not a required dependency.

## Delivery states

Implementation, visual verification, and code checks have separate results. The skill reports full completion only after all applicable checks pass; unavailable scripts require an explicit alternative check, not a fabricated test result.

| Situation | Delivery label used by the skill |
| --- | --- |
| Implementation gaps | 部分完成 |
| Applicable code checks failed or not run | 检查受阻 |
| Implemented, but rendering or some comparisons are missing | 已实现，视觉待验证 |
| Compared at an assumed viewport; acceptance dimensions are unconfirmed | 已实现，视觉待验证（假设 viewport 已对照，验收尺寸待确认） |
| Compared, but blocking discrepancies or trade-offs need approval | 已实现，存在待确认差异 |

Labels may coexist for different scopes. Confirming an assumed viewport does not replace the actual comparison: screenshot conditions must match the accepted dimensions, with a retest if needed. The report preserves remaining differences, accepted deviations, assumptions, and reproduction conditions before temporary artifacts are removed.

## Renamed from earlier names

This skill shipped earlier as `frontend-image-to-code`, then briefly as `design-to-implementation`. It is now `design-image-to-code`, matching its actual job: turning a designer's image into code. Remove whichever copy you have and install the current one:

```bash
rm -rf ~/.pi/agent/skills/frontend-image-to-code ~/.pi/agent/skills/design-to-implementation
cp -R skills/design-image-to-code ~/.pi/agent/skills/
```

Then update the routing hint in `~/.pi/agent/AGENTS.md` so it points at `design-image-to-code`.
