# Design Image To Code

## 单一职责

把设计师提供的设计图准确翻译成现有项目中的前端实现：

```text
设计图与可选标注 → 设计图解析 → 可实现规格 → 项目映射 → 实现 → 渲染对照与迭代
```

本技能不负责从零设计页面、通用项目规划、独立代码审查或设计系统建设。

## 工作契约

### 输入与输出

- 输入：设计图、目标项目与页面范围；已知的 viewport、设备、状态和交互要求。
- 可选证据：Prototype、Figma/MasterGo/蓝湖标注、设计 token、切图包及字体文件。
- 整页还原缺少目标图时，先索取设计图；局部修正若已明确对象、状态和期望结果，可直接处理。没有对应目标图时，只报告该项要求的复测结果，不称为整页已对照。项目落点不明时，先检查当前目录，再确认目标页面。
- 输出：目标页面/组件、实际验证范围、实现推断与还原差异清单。
- 保留项目技术栈、组件契约、路由、状态、权限与业务逻辑。

### 设计边界

- 以设计图为还原目标，不生成另一套设计图替代它，也不套用模型的默认审美。
- 对设计图未表达的任何内容，只补充维持功能所必需的最小实现，不引入新的视觉方向。
- loading、空态、错误态、无权限、溢出等未覆盖状态，保留已有行为并复用现有组件家族、间距与色彩角色。
- 所有外推记为实现推断；多张图按同一设计的证据集合处理，不各自发明页面。

### 证据裁决

现状截图用于复现问题，设计图或用户明确说明才是目标；圈线只标出位置时，不据此猜测应新增还是移除元素。
先对齐页面、区域、版本、状态和 viewport。用户明确要求优先；采用有版本依据的新版，不以清晰度推定新旧。
无法区分版本差异与状态差异时，先确认，不拼接或平均两套方案。

同一版本、同一状态下：

| 决策 | 依据 |
| --- | --- |
| 区域组成、层级、内容、非数值形态 | 设计图；清晰局部图只补充对应区域，保留整页上下文 |
| 尺寸、字号、颜色等可赋值属性 | 该区域明确标注 → 明确适用的 token/规范 → 设计图近似测量 |
| 图片、图标、字体与区域的对应关系 | 标注中的资源引用或切图包映射，结合设计图核对，再查项目已有资源 |
| 交互与状态流转 | 用户说明、Prototype 或交互标注；未表达部分保留项目行为 |
| 技术与业务约束 | 现有代码、组件 API 和配置；当前样式不自动覆盖设计图 |

字号、颜色虽影响外观，仍属于可赋值属性。例如标注为 16px，目测像 18px，先采用 16px，不以“外观优先”改值。
结构与非数值形态按设计图实现；若文字标注要求另一种结构，记录冲突并确认，不静默择一。

每个已发现的跨来源冲突都进入差异清单，注明来源、采用值/方案与冲突表现。
先排查版本、倍率、字体、状态或资源错配；仍影响主要结构、品牌、关键换行或交互时，暂停相关区域并确认。
低影响冲突可暂按上述规则继续，但须报告，不因已选定依据就将冲突视为解决。

DOM/bounding box 与 computed style 仅验证实现结果，不是设计证据；缺乏明确值时，记录相对关系与测量近似值。

### 事实与推断

- **设计事实**：图中观察、明确标注或适用 token；测量值注明近似。
- **项目事实**：可由代码、组件 API 或配置验证。
- **实现推断**：证据未定、但实现需要作出的选择，注明依据与影响。

先查能查到的事实，只把需要用户决定的取舍集中提问，遵循适用的 AGENTS.md 提问约定。
没有相关约定时，优先用可用的结构化提问工具，否则在对话中集中询问。
影响主要结构、品牌或行为契约的未知项阻塞相关区域；低影响且可逆的项可显式推断，继续其余工作。

## 执行流程

### 1. 读取设计图和目标项目

先读取设计图，为每张图记录：

- 页面/区域、版本与状态；完整页面、局部、多个状态或响应式视图。
- 图像像素尺寸、CSS viewport、导出倍率；是否包含设备外框、浏览器栏或整页滚动内容。
- 可辨识内容、可能的占位内容，以及随附标注、资源与交互说明。

再检查项目最小必要范围：入口与父级布局、目标组件及直接依赖、资源与主题、组件库 API、package.json 与锁文件。
沿用已有启动和检查脚本，不扫描整个仓库或预先安装新框架、组件库、浏览器工具。

**尺寸未知**：

- 可依据项目预览配置和图中比例假设 viewport，记录尺寸、依据与受影响区域。
- 图片像素与 CSS 像素的比例确认后才换算；整页高度不等于 viewport 高度，导出倍率不自动等于 DPR。
- 若多种解释会改变分栏、断点、固定区或关键换行，先确认相关区域。

**图像不清晰**：

- 先查原图与局部图；允许临时裁剪、放大，记录区域与缩放比例并保留整页上下文。
- 放大不增加原图信息。关键细节仍不可辨时请求清晰素材；其余按「事实与推断」处理。

**本步退出条件**：目标入口、技术栈和保留边界已定位；每张图对应页面、状态与 viewport，未知项已显式记录。

### 2. 建立设计图规格

编辑前，按页面、viewport 与状态分组，列区域 ID 清单、视觉排列/阅读顺序及覆盖关系，再逐区域展开。
弹层标明所属页面与覆盖关系，局部图关联对应区域；不把图片上传顺序当作页面顺序，不补画图外未知区域。
从外到内分析，只记录本任务需要的规格：

- **几何**：背景、主容器、最大宽度、边距、分栏、对齐轴、固定区、滚动区、层叠与宽高约束。对会随容器变化的区域，区分固定尺寸与应保持的布局关系；单张图中的列宽、控件宽度或同行排列，只证明该可用宽度下的结果。
- **视觉**：颜色角色、边框、圆角、阴影、遮罩、图片比例与裁切、图标形状与对齐。
- **按钮（图中存在时）**：填充/描边、尺寸与内边距、主次层级、图标与文字间距；按图核对，不默认沿用组件库外观。
- 背景、描边和装饰注明所属元素与状态；使用切图时，在该状态的实际显示尺寸下核对轮廓，避免拉伸变形或重复绘制图中已有的装饰。
- **排版**：字体与可用字重、字号、行高、字距、原文、行数、换行位置、文本框宽度与截断。
- **行为**：可见状态、触发与结果、长文本、溢出、内容数量变化及相邻区域影响。

静态图不证明 hover、focus 或点击后的行为；行为来源标为图中可见、交互说明、项目已有或实现推断。
换行先由字体、容器和内容解释；仅在证据明确要求时硬编码换行，兼顾长文本与多语言。

多图共享字体层级、间距、圆角、颜色角色、图标风格与组件家族；局部清晰图不改变整页语言。

#### 资产与文字

- 先按「证据裁决」核对标注资源引用/切图映射，再查项目资源、字体声明与引用；记录路径和目标区域。
- 可辨识文案按原文实现；示例数据映射真实字段，显隐遵循权限，不用泛化文案替代尺寸敏感内容。
- 形状、尺寸与语义匹配时复用组件库图标；不匹配的替代不能标为原稿资产。
- 缺品牌图、主视觉或影响主要换行的字体时，确认来源或可接受替代，继续不受影响的区域。
- 低影响缺失可用项目已有、来源明确的替代，记录差异；无合适替代则明确待补，不随机找图或生成素材掩盖缺失。

#### 规格记录

```text
区域 ID：设计图与版本 / 区域 / viewport 与状态
几何与视觉：布局约束 / 对齐轴 / 样式属性
内容与行为：原文与换行 / 资产路径 / 状态来源、触发与结果
关键取值：数值与单位 / 来源定位 / 事实类别 / 确定或近似
未知或冲突：依据与影响 / 暂用方案 / 是否阻塞
```

区域 ID 贯穿代码映射与差异清单；不要为无证据的固定尺寸或断点制造精确值。

**本步退出条件**：每个待实现区域有规格，关键取值可追溯；未知项和冲突有处理方式，阻塞项未被猜测掩盖。

### 3. 把设计图映射到现有代码

建立映射，再列实现顺序和至多三个高风险区域，小组件不凑数量：

```text
区域 ID → 页面/组件与文件 → 样式或状态改动 → 验证方式
```

先处理主容器、父级布局及辨识度高的区域，再处理固定/滚动区、遮罩、弹层等跨组件约束。
映射不明时补查项目或提问，不直接堆 CSS。

- 优先复用组件；默认样式与设计图冲突时，依次使用公开配置/插槽、局部主题变量、作用域内样式覆盖。
- 局部覆盖保留语义、键盘可达性、状态和业务逻辑；注意弹层挂载，避免影响其他页面。
- 先找同类组件再决定新增；改全局主题、替换已有组件或改变行为契约前，确认取舍。
- 布局责任放在正确父级；不以局部绝对定位修补父级错误，不重写路由、API、权限或数据流。

按实际技术栈检查，以下不是技术栈限制：

- **Vue**：SFC、scoped、响应式、slot、Teleport 与父级布局。
- **Element Plus / Avue / ant-design-vue**：已有封装、主题、默认 padding/line-height、z-index、弹层挂载与状态样式。
- **uni-app**：目标平台、生命周期、单位、安全区、原生组件与多端限制。
- **其他前端栈**：沿用其组件、状态、样式和构建约定，不套用上述框架假设。

**本步退出条件**：所有待改区域有文件、复用/覆盖方式与验证路径；全局影响没有被当作局部修改。

### 4. 实现设计图对应状态

按依赖顺序实现，每层完成后检查是否破坏上一层：

1. 容器、宽高、分栏、对齐、滚动与定位。
2. 背景、边框、字体、颜色、圆角、阴影与图标。
3. 真实文字、换行、图片比例与截断。
4. 目标状态与真实交互，保留项目契约。
5. 设计图给出的响应式视图，以及维持可用性所必需的断点。
6. 设计图、交互说明或现有产品明确需要的动效。

保留各区域的辨识度、留白、密度与组件差异，不替换成通用模板或预设极简风格。
每完成一个高风险区域，按区域 ID 核对规格；出现几何偏差先查父级，不堆负 margin 或局部偏移。
收到改稿时只重做变更区域及受影响约束，复查共享样式影响，已通过部分保持不动。

**本步退出条件**：目标区域与状态已实现，长文本、溢出和必要窄屏约束有处理；控件保持真实交互。视觉通过仍须下一步验证。

### 5. 渲染、对照和迭代

优先通过项目已有入口渲染，用当前环境可用的浏览器或截图能力；截图前确认画面中出现了目标组件及其指定状态。
入口受阻时，可用临时 harness 挂载本次修改的真实组件或构建产物，复现影响该差异的条件（如主题、父容器可用宽度或状态数据）。只对实际复现的范围给出视觉结论；独立仿写的静态页面不能验证交付代码。
构建成功不代表已渲染；无法渲染时继续可完成的实现与检查，按末章分级交付。

#### 对照条件

- 固定 CSS viewport、DPR、locale、权限、数据和交互状态；等待字体/图片加载并稳定动画后截图。
- 设计图与渲染截图逐项配对：整页/局部、滚动位置及可比区域一致，排除外框和浏览器栏。
- 复测用户指出的偏差时，复现其交互状态和容器可用宽度；将目标图与实拍的对应局部并排，保留判断对齐或遮挡所需的相邻元素。
- 每个目标区域、viewport 与状态分别记录结论；一张截图不代表全部通过。
- 原始 viewport 未知时记录「假设 viewport 下已对照」及具体尺寸，不冒称同 viewport 精确验证。

#### 差异迭代

按父到子、先大后小定位，每轮优先修当前层最重要的差异：

1. **几何层**：区域完整性与排列/覆盖关系、画布、主容器、分栏、对齐轴、固定/滚动区、关键宽高与跨区域间距节奏（保留设计图中的差异，不强行统一）。
2. **视觉层**：字体与换行、按钮、背景、边界、颜色、图标、圆角与阴影。
3. **状态层**：设计覆盖的状态，以及长文本、溢出、窄屏与内容量变化。

先并排观察；可用时以叠加图定位偏移、像素 diff 辅助量化、DOM/bounding box 和 computed style 定位代码原因。
像素 diff 前对齐尺寸和缩放；抗锯齿、压缩差异不直接等同布局错误，低差异率不能代替关键区域检查。
只有实际运行并记录方法、参数与结果，才报告像素差异数据；不凭肉眼宣称像素级一致。

每轮更新同一份清单：

```text
区域 ID / viewport 与状态 / 预期与实际 / 证据来源
影响（阻塞或一般）/ 原因与代码位置 / 暂用方案或修正
复测（缩小、未缩小、已解决或待确认）/ 用户接受的差异
```

- 主要结构、品牌、关键换行或交互受影响时标为阻塞，父级修正后重查子组件。
- 连续两轮主要差异未缩小时停止微调，报告原因与所需证据；停止不等于验收通过。
- 列表、标签栏、表格、弹层另查最小内容、长内容、溢出和相邻固定控件。
- 设计图未覆盖的状态只报告功能/布局检查，不称为已对照设计图。

**本步退出条件**：每个目标有对照结论或未验证原因，差异有复测记录；整体验收按下文判断。

## 完成标准与分级交付

分别记录三项验收，不以一项代替另一项：

| 验收项 | 通过条件 |
| --- | --- |
| 实现 | 约定区域与状态已落地，保留业务与组件契约，无未处理的实现阻塞 |
| 视觉 | 每个约定设计图、区域、viewport 与状态均实际对照，无未解决且未经用户接受的阻塞差异 |
| 代码检查 | 项目已有且适用的 lint、typecheck、build 或测试通过，记录实际命令与结果 |

- 一般差异、已接受差异与实现推断仍须报告，不能因通过验收而隐藏。
- 假设 viewport 下的对照不自动通过视觉验收；用户确认验收尺寸后，核实截图条件与该尺寸一致，必要时重测。
- 无适用检查脚本时标为不适用，执行并说明替代检查及覆盖范围，不为本任务引入新工具链。
- 检查失败或应运行而未运行不能计作通过；替代检查不能冒称 lint/测试通过。

实现、视觉及适用代码检查均通过，才报告「还原完成」；检查不适用时，须已有明确的替代检查结果。
否则按下表交付，状态可并存，分别注明受影响范围：

| 当前情况 | 交付状态 |
| --- | --- |
| 实现有缺口 | 部分完成 |
| 适用代码检查失败或未运行 | 检查受阻 |
| 已实现，无法渲染或部分目标未对照 | 已实现，视觉待验证 |
| 已实现，已在假设 viewport 对照，但验收尺寸未确认 | 已实现，视觉待验证（假设 viewport 已对照，验收尺寸待确认） |
| 已实现并对照，仍有阻塞差异或取舍未确认 | 已实现，存在待确认差异 |

## 交付报告

- 交付状态，以及实现、视觉、代码检查三项结论。
- 修改的文件与区域 ID；已对照的 viewport、DPR、状态和关键数据条件。
- 使用的检查方式/命令与结果，未验证范围、实现推断及原因。
- 差异清单：来源、预期/实际、影响、处理、复测与待确认事项。

每个目标区域与状态都能找到结论；保存文字结论与复现条件后再清理本次创建的临时 harness、截图、探针和日志。
用户要求保留的产物、原始设计图、切图和项目既有测试产物不清理。
